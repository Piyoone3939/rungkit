# 設計メモ

## 目標

SolidCraft（AIが操作できるOSSの3D-CAD）と同じ型を、ラダーで作る。

- 画面・CLI・MCP が同じコマンド処理を共有する
- AIは座標やクリックではなく、決まった結果になる命令で編集する
- AIが自分の結果を確かめられる（検証エラー、シミュレーション、形式検証）

## 決めたこと

| 項目 | 決定 | 理由 |
|---|---|---|
| ラングの表し方 | 直列・並列の木。座標は持たない | 実務のラダーはほぼこれで書け、三菱リスト形式と機械的に変換できる。配置は木から計算する |
| 直列・並列で書けない回路（ブリッジ回路） | 対応しない | 三菱リスト形式でも書けず、実務でもほぼ使われない。PLCopen XML 読み込み時は `E_NON_SERIES_PARALLEL` にする予定 |
| 最初のプロファイル | `melsec-iqr` と `iec` | 国内で多い三菱と、標準。FX5（X/Y が8進）は後から足せる |
| タイマー・カウンタの置き方 | 右端の出力（三菱流）だけ | IEC流の「ラングの途中に置くFB」は後から |
| AI向けの入出力 | `.ldt` テキストと JSON | ASCIIアートのラダーはAIが書けない（arXiv 2410.15200）。論理式なら書ける |
| 実装言語 | Go（標準ライブラリのみ） | 手元にあり使い慣れている。MCPは公式Go SDK、画面はWebAssemblyで後から |

## 木の形のルール

- `Series` は最後の要素だけが出力側なら出力側、全部が条件なら条件側
- `Parallel` は全部条件なら条件側、全部出力なら出力側（出力の分岐）。混ざったら `E_MIXED_PARALLEL`
- ラング全体は出力側でなければならない（`E_NO_OUTPUT`）
- 正規化: 直列の中の直列・並列の中の並列は平らにし、要素1つの入れ物は外す

テキスト形式の文法はこのルールに反する木を作れない。JSONから来た木は `check` で弾く。

## ID

- 読み込み時に `r1, r2...`（ラング）と `e1, e2...`（要素）を振る
- 編集してもほかの要素のIDは変わらない。新しいIDは既存のIDと重ならない
- 要素のIDはファイルに保存しない（gitの差分を汚さないため）

## 三菱リスト形式への変換

- 条件側: 先頭は `LD`、直列は `AND`、並列は `OR`。複数要素のかたまり同士は `ANB` / `ORB`
- 出力の分岐: 最後以外の枝が条件を足すときだけ `MPS`、途中で `MRD`、最後に戻すとき `MPP`
- 条件なしの出力は `LD SM400`（常時ON）

## STへの変換

- ラングを上から順に文にする。出力はその場で書く（ラダーと同じ）
- 出力の分岐は、共通の条件を一時変数 `_rN_k` に保存してから各枝で使う（MPSと同じ意味になる）
- 立上り・立下りは R_TRIG / F_TRIG、パルス命令（`MOVP` など）も R_TRIG
- 三菱のタイマー設定値は100ms単位として `T#...ms` に直す
- カウンタの `RST` はまだ書き出せない

## シミュレーター

- 時間は仮想時間。1スキャンの時間は固定（既定10ms、`.ldtest` の `scan` で変更）。実行するたびに同じ結果になる
- 命令はすべて毎スキャン実行する（評価を省略しない）。立上り接点・パルス命令は要素IDごとに前回の値を持つ
- タイマーは入力が入ったスキャンで計測を始め（経過0）、以後1スキャンごとに足す。そのため出力は「設定時間＋1スキャン」後に見える（実機と同じ）
- 三菱のカウンタは設定値で止まる。IECの CTU は 32767 まで数える
- 実行時エラー（0で割る など）はスキャン番号・ラングID・要素IDを付けて返す
- `.ldtest` はテストごとに新しいシミュレーターで実行する。結果はJSONでも出せる（MCPの `run_testcases` でそのまま使う予定）
