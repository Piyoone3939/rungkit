## 3. 言語

- 画面・CLI・MCP のメッセージは、日本語の文をそのまま ID にして英語の辞書を引く（[internal/domain/i18n](../internal/domain/i18n/)）。コード中の日本語の文字列すべてに英訳があること、`%s` などがそろっていることをテストで確かめる
- 言語は `-lang ja|en` → 環境変数 `RUNGKIT_LANG` → `LANG` などの順に決め、どれもなければ OS の設定（Windows のユーザーロケール）を使う
- README と docs は日本語版と英語版の両方を置く（`*.md` と `*.en.md`、README は英語が `README.md`、日本語が `README.ja.md`）
- MCP の instructions とツールの説明は英語（AI が読むもの。どの言語の利用者でも同じ）

## 4. 安全

- rungkit は**実機の PLC と通信しない**（書き込み・モニタ・強制などのオンライン機能を持たない）。書き出したものは、技術者が確認して、メーカーのツール（GX Works3 など）で取り込む前提
- AI が書いたラダーは、`check`（検証）とシナリオ（`.ldtest`）で確かめてから使う。それでも安全回路（非常停止など）は、ソフトではなく配線とメーカーの安全機器で作る
- 将来オンライン機能を入れるとしても、読み取り（モニタ）だけから始め、書き込みは別に判断する
- MCP サーバーは指定した作業フォルダの外のファイルを読み書きしない（`rungkit mcp -root DIR`）
- 三菱電機・MELSEC・GX Works などは各社の商標。rungkit は各社と関係がない

## 5. 配布

SolidCraft は、各 OS 向けの実行ファイル（GitHub Releases）・ブラウザで動く版・Claude Code に1行で登録する MCP をそろえ、Show HN と技術系メディアで広がった。rungkit も同じ形にする。

1. **GitHub Releases** に Windows / macOS / Linux の実行ファイルを置く（GoReleaser、タグを打つと自動で作る）
2. **`go install github.com/Piyoone3939/rungkit/cmd/rungkit@latest`**
3. **ブラウザ版**（GitHub Pages）。インストールせずに試せるのがいちばん広がる
4. **MCP の1行登録**（`claude mcp add rungkit -- rungkit mcp`）を README の最初に書き、公開時に MCP のレジストリにも載せる
5. 公開のときに Show HN（英語）と Zenn / Qiita（日本語）で紹介する

## 6. OpenPLC との関係

OpenPLC Editor は AI 機能を持ち始めているが、自社の AI に閉じていて、MCP も三菱対応もない。rungkit は**エディタを置き換えるのではなく、「AI がラダーを書いて自分で確かめる層」と「国内メーカー対応」を担う**。PLCopen XML で Beremiz・OpenPLC・CODESYS とやり取りできるので、利用者は好きなエディタと組み合わせられる。

## 8. 画面

**ブラウザ版を先に作る**（Go を WebAssembly にして、GitHub Pages で配る）。

- インストールが要らない。工場や学校の PC は管理者権限がなくソフトを入れられないことが多いので、ここが特に大きい
- SolidCraft も、まずブラウザで試せることが広がった理由の1つ
- 同じ画面を後からデスクトップアプリに包める（必要になったら Wails などで）

## 9. 互換性

- 0.x の間は `.ldt`・JSON・`.ldtest`・MCP ツールの形を変えることがある。変えたら CHANGELOG に書き、`rungkit fmt -w` で新しい形に直せるようにする
- v1.0 で形を固定し、以後は古いファイルも読めるようにする

## 10. 対応範囲

| | 内容 |
|---|---|
| やる | ラダー（LD）、三菱 iQ-R / FX5、IEC、PLCopen XML、シミュレーター、MCP、ブラウザ画面 |
| 後でやる | ラングの途中に置くファンクションブロック（IEC 流、画面の後）、キーエンス・オムロン |
| やらない | SFC・ST の編集（ST は書き出しのみ）、実機との通信 |
