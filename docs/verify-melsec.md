# 三菱の実物との突き合わせ手順（無料でできる範囲）

[English](verify-melsec.en.md)

rungkit の三菱対応が本物と合っているかを、**GX Works3 の体験版**（無料）で確かめる手順です。実機（PLC本体）は使いません。

確かめることは2つです。GX Works3 を入手できないときは、[C. マニュアルで確かめる](#c-マニュアルで確かめるgx-works3-がなくてもできる) の方法があります。

| | 確かめること | 使うファイル |
|---|---|---|
| A | rungkit が書き出した**命令の並び（リスト）**が GX Works3 で受け付けられ、同じラダー図になるか | [examples/verify/melsec-semantics.ldt](../examples/verify/melsec-semantics.ldt) |
| B | rungkit の**シミュレーターの動き**が GX Works3 のシミュレーターと同じか | 同上と [melsec-semantics.ldtest](../examples/verify/melsec-semantics.ldtest) |

結果は最後の「記録表」に書いて、Issue か会話で共有してください。

---

## 0. 準備

1. 三菱電機 FA サイトの「ソフトウェアアップデート」ページから **GX Works3 体験版（日本語版）** をダウンロードします（FA会員登録が必要、無料）。
   - ページ: [シーケンサ MELSEC ソフトウェア ダウンロード](https://www.mitsubishielectric.co.jp/fa/products/software/plc/update_index.html)
   - 体験版の使える期間・機能の制限は、配布ページの説明で確認してください。**シミュレーション機能が体験版で使えるか**もここで確認します（使えなければ B はできません）
2. インストールして起動し、**新規プロジェクト**を作ります。
   - シリーズ: **RCPU**、機種: **R04CPU**（iQ-R ならどれでも可）、プログラム言語: **ラダー**
   - rungkit の `melsec-iqr` は iQ-R 向けです（X/Y が16進数）。FX5 を選ぶと X/Y の番号の書き方が違うので、今回は RCPU にしてください
3. rungkit 側でリストを書き出しておきます。

```sh
go run ./cmd/rungkit export -to melsec examples/verify/melsec-semantics.ldt > melsec-semantics.txt
go run ./cmd/rungkit export -to gxw3 -name Verify -o melsec-semantics.csv examples/verify/melsec-semantics.ldt
go run ./cmd/rungkit test examples/verify/melsec-semantics.ldt examples/verify/melsec-semantics.ldtest
```

---

## A. 命令の並びが受け付けられるか

GX Works3 の操作マニュアルによると、ラダーエディタは命令の並び（リスト形式）を書いた CSV を取り込めます。rungkit の `-to gxw3` はその形式で書き出します（文字コードは GX Works3 自身が書き出すのと同じ UTF-16）。まだ実物で試していないので、A-1 で確かめてください。取り込めなかったときは A-2 で手入力します。

### A-1. CSV を取り込む

1. ラダーエディタを開き、「編集」→「ファイル読出」を選びます
2. ファイルの種類を「CSV（タブ区切り）(*.csv)」にして `melsec-semantics.csv` を開きます
3. 「不正な命令の変換方法」を聞かれたら「行間ステートメントに変換」を選んで「はい」を押します（取り込むと、そのプログラムの中身は置き換わります）
4. 取り込んだら「変換」（F4）します

記録すること: 取り込めたか、エラーが出たらその文面、変換エラーの有無、ラング（V1〜V9）のコメントが行間ステートメントとして入ったか。うまくいかなければ、GX Works3 で「編集」→「ファイル書込」（CSV）をしたファイルの先頭10行ほどを教えてもらえると、rungkit 側を合わせられます。

### A-2. 手で命令を入力する（取り込みがなくても必ずできる）

GX Works3 のラダーエディタでは、命令をキーボードで打てます（ラダーの空いている所で文字を打つと命令の入力欄が開きます）。`melsec-semantics.txt` の行を上から順に、`LDP X0` → Enter → `INC D10` → Enter … のように打ってください（`;` で始まる行はコメントなので飛ばします）。

確かめること:

1. **どの命令もエラーにならず入力できるか**（特に `LDP` `ANI` `MPS` `MRD` `MPP` `ANB` `ORB` `LD>=` `*` `/` `+`）
2. 入力後に**「変換」（F4）**して、エラーが出ないか
3. 表示されたラダー図が、rungkit の `.ldt`（`rung` ごとの式）と同じ形か。特に V8 の出力の分岐（`MPS` を使わずに `RST M5` → `AND M6` → `SET M7` と続く形）が意図どおりの分岐になっているか

コンベアの例（[examples/conveyor.ldt](../examples/conveyor.ldt)）でも同じことをすると、自己保持・分岐・パルス命令も確かめられます。

## B. シミュレーターの動きが同じか

1. A-2 で入力・変換したプロジェクトで、「デバッグ」→「シミュレーション」→「シミュレーション開始」を選びます（GX Simulator3 が起動し、プロジェクトが書き込まれて RUN になります）
2. 「オンライン」→「モニタ」→「モニタ開始」でラダーを表示したまま、デバイスの値を変えて結果を見ます
   - 入力（X）を ON/OFF するには、「デバッグ」→「現在値変更」（またはデバイスを選んで右クリック）を使います
   - D・C・T の値は「デバイス/バッファメモリ一括モニタ」で見られます
3. 下の表の操作を1つずつ行い、GX Works3 で見えた値を「実物」の欄に書きます。「rungkit」の欄は `rungkit test` で確かめた期待値です

| # | 操作 | 見るもの | rungkit | 実物 |
|---|---|---|---|---|
| V1 | **RUN する前に** X0 を ON にしておき、RUN する | D10 | 1（最初のスキャンで立上りを検出） | |
| V2 | X1 を ON→OFF を4回くり返す | C0 の現在値 / C0 接点 | 3 / ON（設定値で止まる） | |
| V3 | RUN 直後 | D20 / D21 | 24464 / 1 | |
| V4 | RUN 直後 | D30 / D31 | -3 / -1 | |
| V5 | RUN 直後 | D40 | -32768 | |
| V6 | X2 を ON（X3 は OFF） → 次に X3 も ON | Y0 | OFF → ON（後ろの OUT が勝つ） | |
| V7 | X4 を ON にして、T1 が ON になるまでの時間 | T1 の現在値の増え方 / ON までの時間 | 1秒（＋1スキャン） | |
| V8 | M5 と M6 を ON にする | M5 / M7 | OFF / ON | |
| V9 | X5 を押して離す、をもう1回 | D50 | 2 | |

V7 について: GX Works3 の iQ-R はタイマーの単位を「パラメータ → CPUパラメータ → 動作関連設定 → タイマ時限設定」で決めます（初期値は低速タイマ 100ms のはずです）。設定値を記録してください。シミュレーターは実時間とずれることがあるので、「現在値が 1, 2, 3 … と 100ms ごとに増えて 10 で ON になるか」を見れば十分です。

## C. マニュアルで確かめる（GX Works3 がなくてもできる）

GX Works3 を入手できないときは、三菱電機の**公開マニュアル**で V1〜V9 の動きを確かめます。実機やシミュレーターでの確認には及びませんが、仕様として書かれていることと rungkit が合っているかは分かります。

### 入手

- 三菱電機 FA グローバルサイトのマニュアルページ（英語）から PDF を取得できます。英語版は会員登録なしで取得できました
- PDF には編集・コピーを制限する保護がかかっていますが、ブラウザや PDF ビューアで**読む**ことはできます。保護を外す必要はありません
- マニュアル番号は版で変わるので、**題名**で探してください

| 略号 | 題名（英語版） | 主に見る所 |
|---|---|---|
| 命令 | MELSEC iQ-R Programming Manual (CPU Module Instructions, Standard Functions/Function Blocks) | 各命令のページ |
| CPU | MELSEC iQ-R CPU Module User's Manual (Application) | タイマ・カウンタ・スキャンの説明 |
| GXW3 | GX Works3 Operating Manual | A の取り込み（CSV・テキスト） |

### 確かめる項目

PDF の中を検索（Ctrl+F）するときの言葉も書いておきます。命令のページは「機能（Processing details）」「注意事項（Precautions）」「エラー（Operation error）」の欄を見てください。

| # | 確かめること | rungkit の動き | 見る所 | 検索語 |
|---|---|---|---|---|
| V1 | RUN する前から ON の入力で、`LDP` は最初のスキャンで ON になるか | ON になる | 命令: `LDP` のページ / CPU: STOP→RUN 時の動き | `LDP`, `STOP to RUN`, `rising edge` |
| V2 | カウンタは設定値に達したら止まるか（それ以上数えるか） | 設定値で止まる | 命令: `OUT C` のページ / CPU: Counter の章 | `OUT C`, `Counter`, `set value` |
| V3 | 16ビットの乗算 `*` は 32ビットの結果を (d) と (d)+1 に書くか、どちらが上位か | (d)=下位、(d)+1=上位 | 命令: BIN 16-bit multiplication | `BIN 16-bit multiplication`, `*(P)` |
| V4 | 16ビットの除算 `/` の商と余りの置き場所、負の数の余りの符号 | (d)=商、(d)+1=余り、-7/2 は商 -3・余り -1 | 命令: BIN 16-bit division | `BIN 16-bit division`, `remainder` |
| V5 | `INC` で 32767 の次は -32768 になるか | -32768 になる | 命令: `INC` のページ | `INC(P)`, `32767`, `-32768` |
| V6 | 同じコイルを2回 `OUT` したとき、後ろが勝つか | 後ろが勝つ | CPU か 命令: `OUT` / double coil | `double coil`, `OUT` |
| V7 | タイマーの現在値はいつ増えるか（`OUT T` を実行したときか END 処理か）、設定値に達した接点がいつ ON になるか | `OUT T` を実行するたびに1スキャン分増やし、入力 ON から 設定値＋1 スキャン目に ON | CPU: Timer の章（精度・処理タイミング） / 命令: `OUT T` | `Timer`, `accuracy`, `END processing`, `low-speed timer` |
| V8 | `MPS` / `MRD` / `MPP` の意味（分岐前の演算結果を記憶して後ろの枝で使う） | 分岐前の通電を使う（途中で M5 が OFF になっても M7 は ON） | 命令: `MPS`, `MRD`, `MPP` のページ | `MPS`, `operation result` |
| V9 | `PLS` は入力の立上りで1スキャンだけ ON になるか、STOP→RUN 時はどうか | 押すたびに1スキャンだけ ON | 命令: `PLS` のページ | `PLS`, `one scan` |
| A | リスト（ニーモニック）や CSV を取り込む機能はあるか、その形式 | まだ分かっていない | GXW3: Import / CSV / テキストの説明 | `CSV`, `import`, `text file`, `instruction list` |

特に V1・V7・V9 は、マニュアルに「STOP→RUN のとき」「END 処理で」といった注意書きがあることが多く、rungkit と違う可能性がいちばん高い項目です。V7 はタイマーの数え方そのものが違うかもしれないので、書いてあることをそのまま写してもらえると助かります。

### 記録のしかた

項目ごとに、**マニュアルの題名・版（表紙の番号と改訂の記号）・ページ番号**と、書かれていたことを自分の言葉で短くまとめてください（長い文をそのまま写す必要はありません）。図や表があれば、ページ番号だけで大丈夫です。

```

V4:
V5:
V6:
V7:
V8:
V9:
A:
```

### C の結果（2026-11-24）

次の版を読んで照合しました。命令 = SH-081266ENG (AC)、CPU = SH-081264ENG (AQ)、GXW3 = SH-081215ENG (AN)。ページはマニュアルに印刷されたページ番号です。

| # | 結果 | マニュアルに書かれていること（要約） | 場所 |
|---|---|---|---|
| V1 | 一致 | 電源ON時にすでにONの入力では、最初のスキャンで実行される（PLS の注意書き。ラッチリレーの例）。一度実行したあと STOP→RUN しても実行されない。rungkit には STOP がないので影響なし | 命令 p.188 |
| V2 | 一致 | 数え上がったら RST まで現在値と接点は変わらない。設定値0は1と同じ | 命令 p.175 |
| V3 | 一致 | 結果は32ビットで (d)+1 が上位 | 命令 p.248 |
| V4 | 一部 | 商は (d)、余りは (d)+1。負の数の余りの符号は書かれていない（rungkit は -1） | 命令 p.250 |
| V5 | 一致 | 32767 で実行すると -32768 | 命令 INC(P) |
| V6 | 一致 | OUT を実行するたびにその時点の演算結果で ON/OFF。Y は最後の OUT の結果が出る | 命令 p.58 |
| V7 | 違い→直した | 100ms の目盛りは END 処理で数え、`OUT T` 実行時に足す。最初のスキャンでも足すので、設定値より早く ON になることがある（精度: -(1スキャン＋100ms)〜+1スキャン）。rungkit を同じしくみに直した | CPU p.385〜390 |
| V8 | 一致 | MPS は直前の演算結果を記憶し、MRD・MPP はそれを読んで続ける | 命令 p.160 |
| V9 | 一致 | 立上りで1スキャンだけ ON、それ以外は OFF | 命令 p.187 |
| A | 分かった | 「編集 → ファイル読出」で CSV（タブ区切り）を取り込める。形式は上の A-1 と `-to gxw3` のとおり | GXW3 p.301〜304 |

設定値0のカウンタ（数える前に ON になっていた）も、この照合で見つけて直しました。
